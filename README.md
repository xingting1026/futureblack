# futureblack — 期貨結算週期溢價看板

每個交易日 21:00（台北）自動更新的靜態頁面：**本結算週期**全部個股期貨標的的
週期溢價與大額特定法人未平倉市值。頁首四張卡：台積電週期溢價、賣壓分數
（歷史百分位）、結算日 12:30 跳水機率、預期幅度（bps 與台指期點數）；
下方為多空 cover 名單與全標的排序表。

## 溢價怎麼算（與內部生產系統同構）

1. 每個交易日：09:05~13:25 每 5 分鐘一格共 53 格，每格取
   `期貨成交價 / 現貨成交價 − 1`（雙方各取該時刻前最後一筆成交）
2. 當日日均 → 落地 `data/daily/{日期}.csv`（**一天一檔增量快取**，commit 回 repo）
3. 週期溢價 = 結算窗內全部日均的平均
4. 大小期並存時以「特定法人方向性口數 × 乘數 × 收盤價」加權（權重全零退回乘數比）

已知與內部版的差異：公開 tick 只有成交價（內部版用買賣報價雙邊平均）、無前一日種子。

## cover 名單（多空各自條件，每晚隨週期溢價更新）

cover ＝ days-to-cover ＝ 特定法人前十大方向性口數換算張數 ÷ 近 20 日均量張數，
衡量「結算日被迫拆倉的量相對市場胃納」。2024-12~2026-08 共 21 期回測定案：

- **空方放空**：週期溢價 ≥0.2% × 賣方 cover ≥0.15 × 取 cover 前 3 檔（回測月t=3.8、月勝率94%）
- **多方做多**：週期折價 ≤−0.2% × 買方 cover ≥0.05 × 取 cover 前 2 檔（月t=2.4、月勝率76%）；
  折價股 >100 檔的月份（全市場逆價差＝除息假折價充斥）多方整月停用
- 執行窗：結算日 12:27~12:30 進、12:56~12:59 出，13:00 前一定出清
- 兩腿並打相關 −0.19，合併月t=3.8、最差月 −24bps（單腿 −72/−140）

## 賣壓分數（結算日 12:30 指數跳水預估）

分數 = Σ(週期溢價 × 特定法人 OI 市值)（僅溢價側）＝「要被拆掉的套利倉 × 拆倉動機」。
以 67 個結算日（2021-02~2026-08，`data/pressure_history.csv`）校準，
取歷史百分位分四檔：Q1 → 跳水(≥15bps)機率 18%；Q4 → 機率 71%。

**預期路徑公式**（同 67 日迴歸，x = log10(溢價側特定法人 OI 市值百萬)，夾限在歷史範圍）：
第一波 12:30→12:35 ＝ 40.2 − 10.6x；12:30→12:55 ＝ 56.1 − 16.2x；
12:30~13:00 最深 ＝ 45.7 − 16.4x（殘差 σ≈14.5 bps），點數＝bps × 近月台指收盤 / 1e4。
研究結論：跳水＝「第一波（由賣壓決定）＋約 20 bps 的普適續跌」，是加法不是乘法；
最深點通常落在 12:50~12:58，13:00 後回彈、收盤前回吐約八成。
校準時點為 T-1，週期初 OI 未拆倉、分數會偏高並超出歷史範圍（頁面會標 ⚠），越近結算越準。
卡片下方的走勢圖（`data/path_profile.csv`）是 67 日按賣壓四分位的平均路徑 12:27~13:05，
粗線為本月分位，垂直線標進場 12:30、第一波 12:35、出場 12:55、底部 13:00。

## 結構

```
src/build.py        主流程：日曆 → 對照表 → 補快取 → 因子 → 產頁
src/calendar_tw.py  交易日與第三個週三結算日曆
src/finmind.py      FinMind API 薄封裝（節流/重試；token 走環境變數）
data/mapping.csv    契約↔股票對照與乘數（每晚自動補新契約）
data/daily/         每日每契約溢價快取（Actions 自動 commit）
site/index.html     產出頁（GitHub Pages 部署，不進版控）
```

## 部署需求（一次性）

1. Repo Settings → Secrets → Actions → 新增 `FINMIND_TOKEN`（需 sponsor 權限的 token）
2. Repo Settings → Pages → Source 選 **GitHub Actions**
